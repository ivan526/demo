# 发货备注 Bookmarklet

这是可运行的首版程序：从发货页面读取字段，按优先级执行规则，展示命中原因和备注预览，并在生成后立即自动复制到剪贴板。多条规则命中时使用中文逗号 `，` 拼接；它不会自动提交发货。

## 使用

1. 页面元素变化时，修改 `config.js` 中对应字段的 CSS 选择器。
2. 运行 `node bookmarklet/build.js`。
3. 新建浏览器书签，将 `bookmarklet/bookmarklet-url.txt` 的整行内容粘贴到书签网址。
4. 打开发货页面并点击书签。

备注生成成功后会立即尝试复制，按钮显示“已自动复制”即表示成功；浏览器权限阻止自动复制时，按钮会提示再次点击。预览框内容仍可编辑，编辑后点击按钮可以重新复制。

页面若有内容安全策略（CSP）或 Bookmarklet 长度限制，可改为由内部静态服务器托管脚本；不要把业务数据发往外部服务。

`bookmarklet-url.txt` 已提交到仓库，可以直接下载使用；修改任意源码或规则后，应重新运行构建命令并提交更新后的文件。不需要、也不应该根据开发者本地提交号执行 `git checkout`，应下载当前 PR 分支或 PR 的 ZIP 包。

## 仍需提供的信息

- 若存在其他发货方式，请提供对应页面元素，以便确认通用定位方式。
- 完整规则表：优先级、条件、精确输出、同时命中时是否全部输出。
- 脱敏的输入与预期备注样例。
- 如果字段只存在于接口响应中，请提供脱敏响应 JSON 和字段路径。

得到这些信息后，只需替换配置和页面适配部分，不需要重写规则引擎。

## 已配置规则

当前已实现“具体单号标识”规则：当发货方式严格等于“委托发货”时，生成：

```text
走委托：WTCCDxxxxx，Axxxxxx
```

`{{entrustedShipmentNo}}` 和 `{{processCode}}` 会替换为页面读取到的真实值，复制内容固定以“走委托：”开头，不包含“发货方式”“委托发货单号”“流程编码”等其他标签文字。任一编号为空时程序会提示缺失字段，不会复制不完整的备注。该规则的优先级为 `-100`，因此多条规则命中时会排在其他普通规则后面，并按配置的中文逗号 `，` 继续拼接。

当前页面适配如下：

| 字段 | 页面定位 |
| --- | --- |
| 流程编号 | `input[name='rdSampleApplyId']` 的 `value` |
| 发货方式 | 从 `a.copy[onclick*='copySendWay']` 向上两级，再读取第一个直属 `span` |
| 委托发货单号 | 优先定位第一条 `.grid-row.igrid-selected` 勾选行；若没有勾选行则默认使用第一条 `.grid-row` 数据行，再读取该行内 `td[field='entrustNo']` 的 `val` 属性；若选中行内该单元格为空，会按同一个 `_row` 编号到拆分表格的其他同行查找非空单号，最后再回退读取单元格文本，避免多行/拆分表格读错或读到空值 |

发货方式通过其旁边“向下复制”按钮的 `copySendWay` 操作定位，不再扫描页面中的全部 `span`。当前版本仅生成并复制备注，不读取或自动填写备注输入框。

### 规则 2：具体申请人标识

发货方式严格等于“PO发货”时，输出带标签提示的申请人 ID 和挂账人：

```text
粘贴“申请人：w00975566, 挂账人： w00975566”标签
```

页面映射已经配置为读取 `input[name='applyUserName']` 和 `input[name='reqUserName']` 的 `value`。形如 `wutong 00975566` 的值会转换成首字母小写加编号的 `w00975566`；已经是 `w00975566` 的值保持不变。任一输入框为空时，PO 发货页面会明确提示字段缺失，不会复制空白或不完整备注。

| 字段 | 页面定位 |
| --- | --- |
| 申请人 ID | `input[name='applyUserName']` 的 `value` |
| 挂账人 | `input[name='reqUserName']` 的 `value` |

### 规则 3：备货接口人

处理历史中找到同时满足以下条件的记录时，输出 `备货接口人：x00123456`：

1. “处理意见”包含当前样机行读取到的“产品型号”；
2. “节点名称”严格等于“备货接口人确认”；
3. 从同一条历史记录的“处理人”读取人员信息，并按申请人同样规则转换为工号。

页面映射会优先使用当前勾选样机行；没有勾选时默认第一条样机行，读取该行内 `td[field='prodModel']`（例如单元格内 `<span>Dolphin-T010</span>`）作为产品型号，并且和委托发货单号一样支持同 `_row` 拆分同行兜底。处理历史行默认按 `tr.grid-row` 扫描，当前页面优先读取 `DESCRIPTION` 作为处理意见、`TASKDEFNAME` 作为节点名称、`ASSIGNEE` 作为处理人，并兼容常见的 `dealOpinion` / `handleOpinion` / `processOpinion`、`nodeName` / `activityName`、`handler` / `handlerName` / `dealUserName` 等字段。

### 规则 6：特殊发货标签

产品型号单元格前面带锁、国家/地区不是“日本”，且收货信息中的收货城市不包含中文字符时，输出 `特殊发货管理`。当前先按产品型号单元格内常见的 `.lock` / `.locked` / `.jalor-icon.lock` / `title*="锁"` / `class*="lock"` 识别锁图标；如果页面锁图标使用其他结构，请继续提供该单元格 HTML。

国家/地区当前尝试读取常见的 `countryName` / `countryRegionName` / `country` / `countryAreaName` 输入框或表格字段；如果测试时提示“国家/地区”缺失，请提供该字段 HTML 以补充选择器。

收货城市当前尝试读取常见的 `receiveCity` / `receiverCity` / `cityName` / `receiveCityName` 输入框或表格字段，并检测 CJK 中文字符。如果测试时提示“收货城市”缺失，请提供收货城市元素及其父级 HTML，以便补充准确的页面选择器。

### 规则 7：安装样机管理软件

以下条件全部满足时输出 `预装APK`：

1. 样机用途不在 `seeding sample`、`MKT-媒体评测`、`店员评测`、`GTM-测试样机`、`零售演示样机`、`消费者营销活动`、`异业合作`、`随身样机` 中；
2. 挂账人地区部不在“欧洲终端业务部”“中国终端业务部”“总部”“IoT GTM部”“电商平台部”“平板与PC GTM部”“全球服务部”“手机GTM部”“运动健康GTM部”“终端BG Marketing部”“终端BG零售业务部”“终端BG渠道部”中；
3. APK 安装的页面值严格等于 `✔`。

所有规则同时命中时，固定按“特殊发货标签 → 安装样机管理软件 → 非销售样机标签1/非销售样机标签2 → 具体单号标识/具体申请人标识 → 备货接口人”的顺序输出，规则之间使用中文逗号拼接。页面字段映射如下：

| 字段 | 页面定位与取值 |
| --- | --- |
| 样机用途 | `input[name='sampleUseName']` 的 `value` |
| 挂账人地区部 | `input#regionName[name='regionName']` 的 `value` |
| APK 安装 | 优先定位第一条 `.grid-row.igrid-selected` 勾选行；若没有勾选行则默认使用第一条 `.grid-row` 数据行，再判断该行或同 `_row` 拆分同行内是否存在 `a.jalor-icon.yes[title='是']`，存在时映射为 `✔` |

APK 安装元素本身没有文本，因此程序不会读取 `textContent`；只有已勾选行内存在带 `yes` 类且 `title="是"` 的图标时，才将该字段规范为 `✔`。
